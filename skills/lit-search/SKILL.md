# 논문 검색 · 원문 확보 · 리뷰

오픈액세스만 보면 놓치는 논문이 많고, 필터가 느슨하면 목록이 길어져서 결국 안 읽게 된다. 그래서 이 스킬은 (1) 여러 도구로 넓게 찾고, (2) 요청 조건 하나로 엄격하게 거르고, (3) 읽을 순서(Tier)를 정하고, (4) 도서관 구독으로 원문 PDF까지 받아서, (5) 한 번에 정리한다. 그중 깊게 볼 논문은 (6) 방법론 중심으로 한 편씩 리뷰한다.

사용자는 방법론을 제일 먼저, 그 다음 결과를 보는 연구자라고 가정한다. Intro와 Discussion은 짧게 줄인다.

## 설정 읽기

시작할 때 `~/.config/lit-search/config.json`을 읽는다. 형식은 이 저장소의 `config.example.json`과 같다.

| 키 | 쓰는 곳 | 없을 때 |
|---|---|---|
| `pdf_root` | 4단계 PDF 저장 루트 | 처음 한 번 묻고, 사용자가 원하면 설정 파일을 만들어 저장한다 |
| `library_proxy.url_template` | 4단계 도서관 프록시. `{url}` 자리에 출판사 URL | 프록시 단계를 건너뛰고 무료 경로만 쓴다 |
| `library_proxy.pubmed_otool` | PubMed "Find it" 버튼용 `otool` 값 | 쓰지 않는다 |
| `notion_parent_page_id` | 6단계 리뷰 저장 위치 | 마크다운으로 PDF 옆에 저장한다 |
| `json_export_dir` | 5단계 JSON 내보내기(선택) | 내보내지 않는다 |

설정 파일에는 경로·URL 템플릿만 둔다. 아이디·비밀번호·이메일은 넣지 않는다.

## 모드 고르기

| 요청 | 모드 | 단계 |
|---|---|---|
| 주제로 찾기 | 검색 | 0 → 5 |
| 저자·연도·저널 목록으로 찾기 | 검색(목록형) | 0 → 5 (Tier 없음) |
| 논문 한 편을 주며 요약·리뷰·방법론 정리 | 리뷰 | 4(원문이 없을 때만) → 6 |
| 검색 후 "이거 리뷰해줘" | 리뷰 | 이미 받은 PDF로 6 |

검색 모드를 마치면 Tier A 중 리뷰할 논문이 있는지 한 줄로 묻는다. 사용자가 고르기 전에는 리뷰하지 않는다.

## 규약 (반드시 지킬 것)

- 사용자 개인정보(이메일, 이름, 소속, 학번·사번, 도서관 아이디 등)를 외부 서비스·API 요청에 넣지 않는다. URL 쿼리, 헤더, 본문 모두 해당한다.
  - API가 이메일을 요구하면(예: Unpaywall `?email=`, NCBI E-utilities `email=`, Crossref polite pool `mailto=`) 보내기 전에 사용자에게 묻고 허락을 받는다. 허락 없이는 이메일이 필요 없는 경로(PMC idconv, Europe PMC, 출판사 페이지, `mailto` 없는 Crossref)로 대신한다.
- 검색어에 미발표 연구의 세부(코호트 크기, 내부 결과 수치 등)를 넣지 않는다.
- 로그인이 필요한 곳(도서관 등)은 사용자가 직접 로그인한다. 아이디·비밀번호를 묻거나 입력하거나 저장하지 않는다.
- 외부로 무언가를 보내거나 게시하는 동작(메시지 전송, 공개 페이지 게시, 폼 제출, git push)은 실행 전에 사용자 확인을 받는다.
- 위 규약을 어겼으면 바로 사용자에게 무엇을 어디로 보냈는지 알린다.

## 0. 요청 파악 → 포함 조건 한 줄

- 실행일(`YYYY-MM-DD`)을 처음에 한 번 정해 두고 끝까지 그 값을 쓴다. 자정을 넘겨도 다시 구하지 않는다.
- 주제형 요청: 핵심 개념, 동의어, 연도 범위를 정하고 포함 조건을 한 줄로 쓴다.
  - 예: "성인 2형 당뇨에서 SGLT2 억제제의 심부전 입원 위험을 무작위 배정 또는 표적 시험 모방 설계로 추정한 연구"
  - 이 한 줄이 이번 검색의 하드 필터다. 애매하면 넣지 않는다. 억지로 엮은 논문이 섞이면 목록 전체의 신뢰도가 떨어진다.
- 목록형 요청(저자·연도·저널 목록): 각 항목을 정확히 한 편으로 특정하는 게 목표다. 필터와 Tier는 적용하지 않는다.
- 기간을 주지 않으면 최근 3년을 기본으로 한다.
- 애매한 것만 한 번에 묻고, 나머지는 정해서 진행한다. 원문 PDF는 기본으로 받는다. 사용자가 "링크만"이라고 하면 4단계를 건너뛴다.

## 1. 검색 (여러 경로)

사용 가능한 MCP를 ToolSearch로 불러와서 쓴다. 인증이 필요하다고 나오면 `authenticate`를 실행해서 사용자에게 링크를 준다. 없는 MCP는 건너뛴다.

| 도구 | 쓰는 목적 |
|---|---|
| PubMed (`mcp__claude_ai_PubMed__*`, 환경에 따라 `mcp__PubMed__*`) | 임상·의학 주제의 기본 검색. MeSH + 자유어 조합 |
| Scite (`mcp__claude_ai_Scite__*`) | 인용 맥락, 후속 연구에서 지지/반박 여부, 철회·정정 공지 |
| Consensus (`mcp__claude_ai_Consensus__*`) | 연구 질문형 검색, 놓친 논문 보완 |
| bioRxiv (`mcp__claude_ai_bioRxiv__*`) | 출판 전 preprint |
| arXiv, OpenReview, ACL Anthology, PMLR (웹) | 딥러닝·통계 방법론 주제일 때 1순위. MCP가 없으니 WebSearch/WebFetch 또는 arXiv API(`export.arxiv.org/api/query`) |

- 주제에 따라 출처 비중을 바꾼다. 임상 주제는 PubMed가 1순위, 모델·방법론 주제(분할 모델, 통계 비교 방법 등)는 arXiv·OpenReview를 1순위로 본다.
- MCP가 하나도 안 되면 NCBI E-utilities(`esearch`/`esummary`)를 curl로 호출한다(이메일 파라미터 없이).
- 검색어는 한 번에 끝내지 않는다. 결과를 보고 동의어·MeSH를 바꿔 2~3번 돌린다.
- 온라인 선공개와 정식 출판 연도가 다를 수 있으니 연도 필터는 ±1년 여유를 둔다.
- 임상 의미 기준으로만 찾으면 방법론 논문을 놓친다. 주제가 기술적이면 질환 조건을 뺀 검색도 한 번 돌린다.
- 훑어본 논문 수(제목 수준 포함)를 센다. 마지막 보고에 쓴다.

### 식별과 중복 제거

- 식별자를 정규화해서 합친다. URL이 달라도 같은 논문이면 하나로 본다.
  - 소문자, 앞뒤 공백·`https://`·끝 `/`·`.pdf` 제거
  - arXiv는 `abs`/`pdf`/`html` 경로와 버전 접미사(`v2`)를 같은 값으로 접는다 (`arxiv.org/abs/2609.01982`)
  - 우선순위: DOI → PMID → arXiv ID → 제목
- preprint와 출판본이 둘 다 있으면 출판본을 대표로 두고 preprint는 링크만 덧붙인다.
- 후보가 여러 편으로 갈려 한 편으로 특정되지 않으면 임의로 고르지 않는다. 후보를 보여 주고 묻는다. 엉뚱한 논문을 확정하는 것이 가장 나쁜 오류다.
- PubMed `lookup_article_by_citation` 응답은 `pmid`·`key` 값이 뒤바뀌어 올 수 있다. 숫자값을 PMID로 취한다.
- `pdf_root` 아래에 이미 받은 논문이 있으면 "이미 있음"으로 표시하고 다시 받지 않는다.

## 2. 선별과 Tier 나누기 (주제형 요청만)

0단계의 포함 조건을 통과한 논문만 남기고 세 칸으로 나눈다.

| 구분 | 뜻 | 편수 | 쓰는 내용 |
|---|---|---|---|
| 우선 검토 (Tier A) | 실제로 읽을 논문. 원문 PDF를 받는다 | 2~5편 | 요약 + 내 연구와의 연결 (필수) |
| 참고 (Tier B) | 초록만 훑을 논문 | 3~8편 | 요약 (연결은 선택) |
| 그 외 수집 목록 | 제목·링크·소속만 | 제한 없음 | 없음 |

Tier A로 올리는 기준 (많이 만족할수록 위):
1. 포함 조건의 핵심을 정면으로 다룬다.
2. 진행 중인 연구에 방법·코드·데이터를 바로 가져다 쓸 수 있다 (공개 코드·모델이 있으면 가점).
3. 기존 방법의 한계를 지적하거나 대안을 낸다.
4. 대상 규모(n)나 검증 설계가 사용자 연구와 비교 가능한 수준이다.

사용자가 Tier 없이 "다 보여줘"라고 하면 나누지 않는다.

### 철회·우려·정정 확인

남은 논문마다 확인하고, 하나만 걸려도 표시한다.
1. Scite: 검색 결과의 `editorialNotices`(retraction / expression of concern / correction)
2. PubMed: PublicationType 의 "Retracted Publication"·"Expression of Concern", 연결된 erratum
3. Crossref(보조): `https://api.crossref.org/works/<DOI>` 의 `update-to`·`relation` (`mailto` 없이)

철회 논문은 빼고 보고 끝에 사유와 함께 적는다. 우려 표명·정정은 넣되 카드에 표시한다. 제목 앞에 "RETRACTED:"가 붙어 식별이 갈리는 경우가 있다 — 그 차이뿐이면 같은 논문으로 보고 철회로 처리한다.

## 3. 후보 확인

후보 목록을 짧게 보여준다: 구분(Tier), 저자 연도, 저널, 영어 원제, 식별자, 왜 골랐는지 한 줄.
- 목록형 요청이면 항목마다 찾은 논문이 맞는지(저자·저널·연도 일치) 표시한다. 못 찾거나 후보가 여러 개면 그렇다고 말한다.
- 사용자가 빼거나 올리라고 한 것만 바꾸고 4단계로 간다.
- 원문을 받을 범위: 기본은 Tier A 전부 (목록형은 전부). 10편이 넘으면 범위를 묻는다.

## 4. 원문 PDF 확보

리뷰 모드에서 PDF 경로를 받았으면 이 단계는 건너뛴다. 파일명만 받았으면 `pdf_root` 아래에서 `find`로 찾는다.

먼저 `claude-in-chrome` 스킬을 불러온다(도서관 프록시를 쓸 때만 필요).

순서 (무료·로그인 불필요한 경로부터, 프록시는 최소로):
1. PMC 무료 전문이나 arXiv PDF가 있으면 그걸 먼저 받는다.
2. 오픈액세스 PDF(출판사 OA, Europe PMC)가 있으면 받는다.
3. 없고 `library_proxy`가 설정돼 있으면 도서관 프록시로 연다.
   - 출판사 논문 URL을 `url_template`의 `{url}` 자리에 넣어 연다 (EZproxy 계열은 보통 `https://<proxy>/login?url={url}` 형태).
   - `pubmed_otool`이 있으면 `https://pubmed.ncbi.nlm.nih.gov/<PMID>/?otool=<값>`으로 열어 "Find it"/Full text links를 쓴다.
4. 도서관 로그인 화면이 나오면 멈추고 사용자에게 Chrome에서 직접 로그인해 달라고 한다. 아이디·비밀번호를 묻거나, 입력하거나, 어디에도 저장하지 않는다. 로그인 세션은 Chrome에 남으므로 보통 하루 한 번이면 된다.
5. 출판사 페이지의 쿠키 배너는 필수만 허용(Reject all)으로 닫는다. PDF 버튼을 누른다.
   - PDF가 Chrome 뷰어로 열리면 그 탭의 URL(서명 토큰이 붙은 PDF 주소)을 curl로 바로 저장 폴더에 받는다. 저장 대화상자는 조작할 수 없다.
6. 안 되는 경우(구독 안 함, 캡차, 링크 없음)는 억지로 우회하지 않는다. "원문 없음 – 사유"로 기록하고 다음 논문으로 넘어간다. Sci-Hub 등 비합법 경로는 요청받아도 쓰지 않는다.

도서관 프록시는 한 편씩 차례로 받는다(병렬 금지). 같은 출판사에서 하루 15편을 넘기지 않는다. 대량 다운로드는 기관 구독 약관 위반이 될 수 있다.

저장:
- 실행마다 `pdf_root` 아래에 하위 폴더를 새로 만들고 거기에 받는다. 폴더 이름은 `YYYY-MM-DD <주제>` (예: `2026-10-21 SGLT2 심부전`). 리뷰 모드에서 한 편만 받을 때도 같은 규칙이다. 사용자가 폴더를 말하면 그곳에 받는다.
- Chrome이 `~/Downloads`에 받았으면 하위 폴더로 옮긴다.
- 파일명: `<제1저자> <연도> <저널약어> - <제목 앞부분>.pdf` (예: `Smith 2024 NEJM - Empagliflozin and heart failure.pdf`)
- 옮긴 뒤 파일이 실제 PDF인지(`file` 명령, 첫 4바이트 `%PDF`) 확인한다. HTML 로그인 페이지가 받아진 경우가 흔하다.

## 5. 통합 정리 (검색 모드)

원문을 받은 논문은 PDF를 읽고 정리한다. 원문이 없으면 초록 기준이라고 표시한다. 요약·방법·수치는 이번에 실제로 읽은 원문이나 초록에서만 가져온다. 기억으로 쓰지 않는다.

### 논문별로 쓰는 항목

| 항목 | 규칙 |
|---|---|
| 제목 | 영어 원제 그대로. 아래에 한국어 제목을 따로 단다 |
| 식별자 | `doi:10.xxx` / `PMID:12345678` / `arXiv:2609.01982` 중 하나 |
| 링크 | 실제로 열리는 URL. DOI 링크(`https://doi.org/...`) 우선 |
| 저널·게재일 | 저널명(또는 `arXiv cs.CV`, `MICCAI 2025`), `YYYY-MM-DD` |
| 저자 | `제1저자 et al.` |
| 소속 | 기관 + 학과를 짧은 구로 (예: `University of Oxford 통계학과`). 산업계면 드러나게. 논문 1면에서 확인하고, arXiv는 `https://arxiv.org/html/<id>`로 1면을 연다. 확인 안 되면 추측하지 말고 `(소속 미표기)` |
| 요약 | 한국어 3~6문장. 무엇을, 어떤 방법으로, 결과 수치가 무엇인지. 원문·초록에 없는 수치를 만들지 않는다. 결과가 부정적이면 부정적이라고 쓴다 |
| 방법·대상 | 데이터 규모(n), 장비·코호트, 검증 방식(내부/외부), 공개 코드·모델 여부 |
| 내 연구와의 연결 | Tier A 필수. 감상이 아니라 이 논문을 인용하면서 던질 수 있는 후속 질문 1~2개 (예: "외부 검증 AUROC 0.68~0.77이 장비가 다른 두 스캐너 사이에서도 유지되는가?") |
| 공지 | 우려 표명·정정이 있으면 |
| 원문 | PDF 파일명 또는 "초록만 – 사유" |

### 쓰지 않는 것 (두 모드 공통)

- 저널 IF·랭킹. 추정치를 적어 두면 나중에 그대로 인용하게 되므로 아예 쓰지 않는다. 필요하면 JCR/Scopus에서 직접 확인하라고 안내한다.
- 초록·본문을 통째로 옮겨 적지 않는다 (저작권). 내 말로 요약한다.
- 굵은 글씨(`**`).

### 채팅 보고 형식

1. 첫 줄: 포함 조건 한 줄
2. 카운터: 훑어본 수 / Tier A 편수 / Tier B 편수 / 원문 확보 편수
3. Tier A, Tier B 논문 카드 (위 항목 순서대로)
4. 그 외 수집 목록: `제목 — 저널 — 소속 — 링크` 한 줄씩
5. 논문 사이에 결과가 엇갈리면 한 줄로 따로 적는다
6. 검색한 도구와 검색어, 철회로 뺀 논문, 원문 못 받은 논문과 사유
7. PDF 하위 폴더 경로
8. Tier A 중 6단계 리뷰로 넘길 논문이 있는지 한 줄로 묻는다

### 노트 저장 (사용자가 원할 때)

이번 실행의 PDF 하위 폴더에 `YYMMDD <주제> 문헌정리.md`로 쓴다.
- 같은 주제로 이미 문헌정리 노트가 있으면 새로 만들지 않고, 이미 있는 논문은 건너뛰고 새 논문만 덧붙인다.

### JSON 내보내기 (선택)

`json_export_dir`이 설정돼 있거나 사용자가 요청하면 [docs/json-schema.md](../../docs/json-schema.md) 형식으로 `<json_export_dir>/<YYYY-MM-DD>.json`을 쓴다. 정적 사이트(예: Vercel 뷰어)에서 읽기 위한 것이다. PDF 경로는 넣지 않고 파일명만 넣는다. 커밋·push는 사용자 확인 후에만 한다.

## 6. 한 편 리뷰 (리뷰 모드)

목표는 "이 논문을 내 데이터로 재현하거나 가져다 쓸 수 있는가"를 페이지 하나로 판단할 수 있게 하는 것이다.

### 입력

- PDF 경로: 그대로 읽는다. PDF 스킬이나 Read로 읽는다. 표와 그림 설명까지 본다.
- 파일명, DOI, PMID, arXiv ID, URL: 4단계로 원문 PDF를 먼저 확보한다.
- 원문을 못 받으면 초록으로만 정리하되, 맨 위에 "초록 기준 – 방법론 세부 없음"이라고 적는다. 방법론 칸을 추측으로 채우지 않는다.
- 여러 편을 주면 한 편씩 따로 만든다.

### 읽는 순서

1. Methods (Materials and Methods, Supplementary Methods 포함) — 가장 꼼꼼히. Supplementary에 전처리·하이퍼파라미터가 있는 경우가 많으니 있으면 같이 본다.
2. Results — 표와 그림의 수치.
3. Abstract, Figure 1(전체 흐름도) — 전체 구조 확인용.
4. Intro, Discussion — 한계(limitation) 문단과 "future work"만 훑는다.

### 정리 규칙

- 수치·설정값은 논문에 적힌 그대로 쓰고 출처를 붙인다: `(Table 2)`, `(Fig. 3)`, `(Methods 2.3)`, `(Suppl. Table S1)`.
- 논문에 없는 값은 만들지 않는다. 적혀 있지 않으면 `논문에 명시 안 됨`이라고 쓴다. 이게 재현 가능성 판단의 핵심 정보다.
- 기술 용어는 영어 원어를 살린다 (nnU-Net, Dice, focal loss, 5-fold CV 등). 설명은 한국어로.
- 핵심 수식이 있으면 LaTeX로 옮긴다 (손실 함수, 점수 계산식, 정규화 식 등). 수식 옆에 기호 뜻을 한 줄로.
- 임상 배경·질환 설명은 "데이터" 칸에 한두 줄로만 둔다.
- 저자 주장과 실제 결과를 구분한다. 결과가 부정적이거나 기존 방법보다 못한 지표가 있으면 그대로 쓴다.

### 저장 위치

- `notion_parent_page_id`가 있으면 그 페이지 아래 하위 페이지로 만든다. 사용자가 그때 다른 페이지를 말하면 그곳에 둔다.
  - 만들기 전에 `notion-search`(page_url에 부모 페이지를 넣어서)로 같은 제목 페이지가 있는지 확인한다. 있으면 새로 만들지 않고 업데이트할지 묻는다.
  - 부모 페이지 본문은 수정하지 않는다. 하위 페이지만 새로 만든다.
  - 처음 쓸 때 `notion://docs/enhanced-markdown-spec`을 fetch해서 표·토글·수식·콜아웃 문법을 확인한다.
  - 페이지 제목: 영어 원제 그대로. 아이콘: 📄
- 없으면 PDF와 같은 하위 폴더에 `<PDF 파일명>.review.md`로 쓴다. 노션 토글은 `<details>`로 바꾼다.
